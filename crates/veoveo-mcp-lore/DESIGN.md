# Lore MCP Design

Lore for agents and people. It starts with seeing what is there: what the repositories a person can read hold, and a gallery of them. It
is where Lore's API grows, as tools over the same reads.

It reads as the person who asked, through the Hub, so Lore's rules decide every read. It keeps nothing.

## Service Identity

```text
repository   veoveo-mcp-lore
slug         lore
URI scheme   lore
permission   lore.files.read
MCP          /lore/mcp
liveness     /livez
readiness    /readyz
port         8808
```

The slug and the Hub's own `/lore/` routes and `/view/lore/` pages share a name and nothing else: this server declares no content, so a
`/view/lore/` page stays the Hub's.

## Standards And Protocols

| Standard or protocol | Implemented profile |
|---|---|
| [Model Context Protocol](https://modelcontextprotocol.io/specification/) | Version `2026-07-28`, JSON-RPC 2.0 over Streamable HTTP, under the hosted MCP contract, through the SDK. |
| [MCP Apps](https://github.com/modelcontextprotocol/ext-apps) `2026-01-26` | `ui://lore/repositories`, in the host's ordinary frame, through the bridge. |
| [MCP Skills extension](https://github.com/modelcontextprotocol/ext-skills) | The skill `browse-repositories`. |
| [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12/) | Tool inputs and results, generated by Schemars from the contract's types. |

## Domain Contract

| Kind | Name | Permission | Answer |
|---|---|---|---|
| Tool | `list_files` | `lore.files.read` | `FileListing`: without a `repository`, the repositories the caller can read; with one, a folder of it on `branch`, `main` by default, folders first |
| Tool, for its App | `thumbnail` | `lore.files.read` | `FileThumbnail`: a picture of a file, in base64, or none |
| App | `ui://lore/repositories` | `lore.files.read` | The gallery |

`thumbnail` asks the [Thumb server](https://github.com/VeoveoAI/veoveo-mcp-thumb/blob/main/crates/veoveo-mcp-thumb/DESIGN.md) as the same person, since a view reads only its own server. This server makes no pictures.

## The App

`ui://lore/repositories` opens on the repositories the person can read, then their folders and files, each folder's card showing pictures of
what it holds. The look and the behavior are [veoveo-hub-ui](https://github.com/VeoveoAI/veoveo-hub-ui)'s gallery. `assets/repositories.js`
says what is Lore's: how to list, what a location is, and the `/view/lore/{repository}/{branch}/{path}` page a file opens on.

It shows `main`. A branch is a tool argument, not yet a choice in the App.

## Factory

`openshell/` holds the toolchain and the script that builds and starts the server. It asks for no GPU, no network rule and no provider.

## Persistence

No tables. The registration's `keys/` under `/sandbox/state`.
